# Declarative Setup Engine and CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deterministic, idempotent boilerplate setup engine and expose it through an interactive and noninteractive `nrb` CLI.

**Architecture:** A pure config-to-plan core owns decisions; filesystem adapters own I/O. CLI input collection delegates to the core and never edits files directly. Existing init and feature commands remain compatible wrappers.

**Tech Stack:** TypeScript, Zod, Node `readline/promises`, Vitest, Node filesystem APIs, Nx workspace conventions.

**Ownership:** Worker E owns schema/catalog/presets; Worker F owns planner/state/apply/node adapter; Worker G owns CLI routing/prompts/doctor; integration owner exclusively owns cumulative edits to `packages/tooling/package.json`, root `package.json`, the compatibility wrappers, and composition tests. Tasks that depend on those manifests run sequentially.

**Autonomous Execution:** Use TDD. Preserve existing commands. Generated output must be deterministic. Unsupported technology combinations fail validation with exact remediation rather than emitting partial projects.

**Validation Evidence:** Unit coverage for every schema branch and operation; component tests over temporary workspaces; E2E setup twice to prove idempotency; dirty-tree, conflict, and rollback tests.

**True Blockers:** Stop only if an existing supported project cannot be represented without a schema-breaking contradiction. Capture the minimal config and conflict; otherwise add a catalog constraint and continue.
